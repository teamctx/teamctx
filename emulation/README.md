# Phase 5 emulation harness

This directory drives the Phase 5 team-validation scenario matrix through the REAL teamctx CLI,
hook, and MCP tool, and records expected vs actual as durable evidence. It is not part of the
`teamctx` package (it is excluded from the build and from coverage); ruff and mypy still apply.

Design and scenarios are binding:

- Plan: `docs/superpowers/plans/2026-07-03-p5-harness.md`
- Spec: `docs/superpowers/specs/2026-07-03-phase5-emulation-program.md` (Revision 2)

## Safety rail

The harness never makes a live network call and never touches real GitHub, GitLab, or Atlassian.
Every offline row runs against:

- local tmp git repos built by `actors.py` (a github.com or gitlab.com origin selects the forge),
- the bundled mock servers (`mockgh.py`, `mockgl.py`, `mockjira.py`, `mockconfluence.py`) reached
  only through the `TEAMCTX_GITHUB_API_ROOT` / `TEAMCTX_GITLAB_API_ROOT` seams or the normal
  `work_start.jira.base_url` / `work_start.confluence.base_url` config seams,
- synthetic PreToolUse events carrying exactly the fields `teamctx.hook` reads.

`runner.py` refuses to run without `--offline`, so the rail is enforced in code. LIVE execution
against the disposable lab repos (real GitHub and GitLab, plus Jira and Confluence once Edgar names
them and write scope is verified) is the CTO's step after review, never the builder's.

## Run it

```
python emulation/runner.py --offline --all          # the whole matrix
python emulation/runner.py --offline --row 01        # one row (repeat --row for several)
python emulation/runner.py --offline --all --out DIR  # write evidence under DIR
```

Each row writes `rowNN/actual.txt` (the captured output, redacted) and `rowNN/verdict.txt` (the
per-span PASS/FAIL). Without `--out`, evidence goes to a fresh temp dir printed on completion.
Implemented rows report PASS; a FAIL exits non-zero.

## Expected blocks

Expected blocks quote the REAL renderer copy, generated by running the pipeline offline, never by
guessing. Per the spec's per-span rule, stable copy spans are byte-exact and variable spans are
templated: `{n}` (digits, e.g. a PR or issue number), `{url}`, `{id}` (an opaque id or short sha).
`evidence.py` compiles a block into a regex (literals escaped, placeholders matched by pattern) and
a row PASSES when every required block matches and no forbidden literal (for example a false
`Looks clear to start.`) appears.

## Environment contract

`actors.SubprocessEnv` builds the env for a CLI/hook subprocess:

- `PYTHONPATH` is pinned to this worktree's `src`, so the harness drives THIS branch's teamctx.
- `TEAMCTX_GITHUB_API_ROOT` / `TEAMCTX_GITLAB_API_ROOT` point at the matching mock, so every
  GitHub or GitLab call is bounded to `127.0.0.1`. A GitHub row passes `api_root`; a GitLab row
  passes `gitlab_api_root` (and `gitlab_token`); the credential env for the forge NOT under test
  is cleared so a real ambient token can never leak into a live call.
- Jira and Confluence rows write `work_start.{jira,confluence}.base_url` to the local mock server
  and set `ATLASSIAN_EMAIL` / `ATLASSIAN_API_TOKEN` to synthetic values only for the configured
  sub-row; the subprocess env scrubs any ambient Atlassian credential otherwise.
- `GITHUB_TOKEN` / `GITLAB_TOKEN` are synthetic operator tokens (they authenticate only to the
  mock). The token keys nothing in the product: collision keys on the PR/MR source branch vs the
  request branch, criteria keys on timestamps, so ONE token stages every actor role (spec rev 2,
  P1-1).
- `TEAMCTX_DISABLE_GH_AUTH=1` keeps token resolution deterministic (no `gh` fallback).
- `TEAMCTX_HOOK_CACHE` is a fresh dir and each hook event carries a fresh `session_id`, so the
  once-per-session marker never turns a second hook run into a silent no-op.

## Live vs offline

Offline runs prove the pipeline against fabricated payloads and tmp repos. Live execution differs
in exactly these ways, and is the CTO's step:

- the lab targets come from env (`P5_GITHUB_LAB_REPO`, `P5_WORKDIR`, and the standard token envs),
  and drivers hard-fail with a plain message when those are unset;
- the mock is replaced by the real API root (drop the `TEAMCTX_GITHUB_API_ROOT` override);
- the redaction map (`redact.py`) is configured with the real Atlassian base URL and project/space
  keys before any evidence is committed. GitHub and GitLab lab slugs are committed as-is.

## observed_at injection (row 11)

Replay determinism needs a pinned `observed_at`. The harness injects it as a PARAMETER to
`render_work_start` (the work_start invocation), never as a CLI flag and never as a new production
env read, so no product code path is altered. The mock's GraphQL page cursor is rewound between the
two runs so the replay re-serves byte-identical pages; the two renders and their sha256 digests must
match.
