# Sprint 02: Dogfood The Terminal Loop

Dates: 2026-06-16 through 2026-06-30
Status: started

## Sprint Goal

Make TeamCtx usable as a real local terminal tool in an owned repository, not
just a fixture-backed proof.

By the end of the sprint, a developer or coding agent should be able to initialize
TeamCtx in a repo, refresh context from the configured GitHub source, read the
working context without long flags, inspect why a card appeared, and prove the
same flow against a seeded open PR in an owned repo.

## CTO Read

Do not widen the product yet.

Sprint 01 proved the product spine: compact source status by default,
policy-gated source opening on demand, a narrow GitHub PR metadata probe, and a
contract-backed terminal surface. Sprint 02 should make that loop reliable enough
to dogfood before adding Jira, Confluence, Obsidian, Slack, GitLab, or Linear.

The honest product risk is not connector count. The risk is that setup friction,
stale local context, unclear source-opening language, or an unreliable demo loop
makes the product feel like another thing to manage instead of useful context at
agent start and resume points.

## Outcomes

1. `teamctx init` creates a safe project config without storing credentials.
2. `teamctx context`, `teamctx why`, and `teamctx open-source` default to the
   local context document instead of requiring `--contract` for normal use.
3. The GitHub PR metadata path is dogfooded against an owned repo with a known
   seeded open PR.
4. The README and scripted transcript match the current command shape.
5. One issue-tracker fixture path exists for product learning without claiming a
   live Jira or Linear connector.
6. The source-opening command language has a product decision: keep generic
   `open-source` or split into source-specific actions such as `open-pr`,
   `open-issue`, and `open-doc`.

## Non-Goals

- No live Jira connector.
- No live Confluence connector.
- No live Obsidian connector.
- No Slack or Teams connector.
- No dashboard.
- No cloud service.
- No broad source search.
- No source body browsing by default.
- No memory, ledger, registry, promotion, or productivity-tracking language.

## Workstream 1: Setup And Local Cache Ergonomics

Owner: CTO

Goal: remove the flags and manual config steps that make the terminal slice feel
like a prototype.

Tasks:

- Add `teamctx init` for `.teamctx/config.json`.
- Ensure config stores token environment variable names, not token values.
- Refuse config overwrite unless the user passes an explicit force option.
- Make `context`, `why`, and `open-source` read the configured local context path
  by default.
- Keep explicit `--fixture` and `--contract` paths for tests and experiments.

Acceptance criteria:

- A user can run `teamctx init`, `teamctx refresh`, `teamctx context`,
  `teamctx why <card-id>`, and `teamctx open-source <card-or-source-id>` without
  manually passing `.teamctx/context.json` after refresh.
- Missing local context tells the user to run `teamctx refresh`.
- Tests prove config initialization does not write token values.

### Checkpoint: 2026-06-16

Status: implemented.

Evidence:

- `teamctx init` writes project config and refuses accidental overwrite.
- `context`, `why`, and `open-source` default to local context lookup.
- Focused verification passed: `tests/test_project_config.py` and
  `tests/test_contract_terminal.py`.

## Workstream 2: Owned-Repo Dogfood Proof

Owner: CTO with CPO dogfood

Goal: prove the GitHub metadata path in an owned repo where we control the demo
conditions.

Tasks:

- Create or identify an owned repository target.
- Seed a harmless open PR touching a known file.
- Configure TeamCtx for that repo.
- Run `refresh`, `context`, `why`, and `open-source` from a local checkout.
- Capture the transcript and the resulting contract document metadata.

Acceptance criteria:

- The rendered context includes an overlapping-work card from the seeded PR.
- The card explains same-repo and same-path provenance.
- Source body remains status-only unless a future source-specific open action is
  designed.
- The run is documented as a dogfood proof, not a general GitHub support claim.

## Workstream 3: Demo Reliability And Product Language

Owner: CPO with CTO support

Goal: make the first terminal demo read like a product, not an experiment kit.

Tasks:

- Update README commands to the Sprint 02 terminal flow.
- Capture a new scripted terminal transcript.
- Decide whether `open-source` remains acceptable for MVP or should split into
  `open-pr`, `open-issue`, and `open-doc`.
- Keep user-facing language plain: working context, show why, source status,
  continue without it.

Acceptance criteria:

- The transcript can be followed without knowing Core Contract, source signal,
  source routing, promotion, or durable-core language.
- The token/time savings promise is framed honestly: TeamCtx reduces repeated
  source lookup when compact context and source status are enough, but it does
  not claim universal token savings.

## Workstream 4: Issue-Tracker Fixture Path

Owner: CTO

Goal: learn the Jira/Linear product shape without expanding live connector risk.

Tasks:

- Add one fixture-backed work-tracker scenario for changed acceptance criteria or
  a structured issue rule.
- Normalize it through Core Contract V0.
- Render it through the same terminal path.
- Keep live Jira and Linear out of scope until the fixture path proves the field
  policy and user language.

Acceptance criteria:

- The issue-backed card includes source, reason, freshness, confidence, and
  body-openability status.
- Arbitrary issue comments remain out of scope.
- The fixture demonstrates exactly which fields would be needed from a live
  connector.

## Workstream 5: Build Plan Alignment

Owner: CTO

Goal: keep the repo's operating plan truthful as product discovery moves fast.

Tasks:

- Replace the stale broad phase map with a live roadmap.
- Link Sprint 02 as the current operating plan.
- Keep later source families visible but explicitly deferred.

Acceptance criteria:

- A new contributor can tell what is built, what is being dogfooded now, and what

## Definition Of Done

- Full test suite passes.
- Ruff and mypy pass.
- `git diff --check` passes.
- Secret scan passes on committed artifacts.
- Docs match the runnable command surface.
- Dogfood proof is documented with limitations.
- Work is committed and pushed at good stopping points.

## Current Risks

- Owned-repo PR setup may require GitHub permissions or branch hygiene.
- The local context file can become stale; Sprint 02 should decide whether
  `status` needs to show freshness immediately or in Sprint 03.
- `open-source` may stay too generic once issue and doc fixtures appear.
- An issue-tracker fixture can accidentally smuggle live-Jira assumptions into
  the product language. Keep it narrow and explicit.
