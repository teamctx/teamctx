# Sprint 01: From Fixture Proof To First Real Signal

Dates: 2026-06-16 through 2026-06-29

## Sprint Goal

Prove that TeamCtx can move from benchmarked fixture behavior to a narrow real
vertical slice without losing the product boundary.

By the end of the sprint, TeamCtx should be able to produce a trusted terminal
context packet for one real source family, while keeping source bodies gated,
source health explicit, and user-facing language plain.

## CTO Read

Do not build all connectors.

The correct sprint is not GitHub plus Jira plus Confluence plus Obsidian. That
would create a wide but weak product. The right sprint is one hard, narrow path:
local repo context plus GitHub/GitLab-style PR metadata, with fixture-backed
proof that source-opening and collision behavior remain safe.

## Outcomes

1. Source-openability survives a larger benchmark slice.
2. Collision behavior is scored correctly: noticing risk is not enough if the
   patch still rewrites a risky API without validation.
3. Core contracts are stable enough to support a real connector without
   smuggling source text or policy decisions through ad hoc structures.
4. A first live Git-host metadata probe can produce an overlapping-work signal
   for opted-in repos.
5. The terminal output still feels like `git status` for team context, not
   search, memory, surveillance, or a dashboard.

## Non-Goals

- No Jira, Confluence, Slack, Teams, Obsidian, or Linear live connector.
- No dashboard.
- No cloud service.
- No broad source search.
- No PR comments, review bodies, issue comments, or document body ingestion.
- No LLM in the broker.
- No memory, ledger, registry, or productivity-tracking language.

## Workstream 1: Benchmark And Product Contract

Owner: CTO

Goal: settle the source-routing contract enough to build against it.

Tasks:

- Run source-openability across a larger slice: collision, changed criteria,
  stale docs, blocked source, inaccessible docs, and project guidance if budget
  permits.
- Add collision-specific scoring that rewards additive or review-blocking
  behavior when an overlapping PR body is unavailable.
- Make validation explicit in quality scoring when code changes are made.
- Decide whether the prompt language should remain `body available` /
  `body unavailable` or shift to more concrete product actions such as
  `Open issue`, `Open PR`, or `Status only`.
- Record the decision in discovery findings.

Acceptance criteria:

- No benchmark scenario fails.
- Collision scenario preserves the existing API, blocks, or creates a review
  note when source body is unavailable.
- Body-available Jira path still opens the source and uses the changed criteria.
- Findings clearly state the product default: compact status first,
  open-on-demand only when useful and allowed.

## Workstream 2: Core Contract V0

Owner: CTO

Goal: define the durable objects behind the terminal packet before live source
work grows around the fixture prototype.

Tasks:

- Draft versioned contracts for:
  - `SourceSignal`
  - `SourceStatus`
  - `SourceOpenTarget`
  - `GuidanceRecord`
  - `SessionContextUse`
  - `ContextCard`
  - `RequestContext`
  - `PolicyDecision`
- Add golden serialization fixtures.
- Add invalid-fixture tests for unknown fields and unsafe policy bypasses.
- Keep `teamctx.core` pure: no filesystem, network, subprocess, randomness, or
  ambient current time reads.

Acceptance criteria:

- Contract fixtures round-trip deterministically.
- Unknown fields cannot bypass policy.
- Every rendered card can explain source, reason, scope, freshness, confidence,
  and whether source body text is openable.
- Existing CLI and benchmark tests still pass.

## Workstream 3: First Live Source Family Probe

Owner: CTO

Goal: prove one real source signal from one source family.

Scope: Git-host PR metadata only.

Allowed fields:

- Repository id or full name.
- PR/MR number.
- State.
- URL.
- Title only if policy allows it.
- Changed file paths.
- Created, updated, merged timestamps.
- Labels if configured.

Excluded:

- PR comments.
- Review comments.
- Review bodies.
- Commit patches.
- Author identity unless explicitly allowed.
- Broad repo search.

Tasks:

- Add a fixture connector shape for forge-review metadata.
- Add a GitHub probe command behind explicit config or environment token.
- Normalize PR metadata into source artifacts.
- Run policy before cache or card rendering.
- Emit overlapping-file `SourceSignal` from live metadata.
- Add source health for unavailable, unauthorized, rate-limited, and stale
  refresh states.

Acceptance criteria:

- A configured repo can produce an overlapping-work card from real PR metadata.
- The connector cannot return body text or comments.
- Missing or failed GitHub access produces source status, not silent confidence.
- Tests run without network credentials using fixtures.

## Workstream 4: Terminal Vertical Slice

Owner: CTO with CPO dogfood

Goal: make the first real workflow feel usable from an agent terminal.

Target flow:

```text
teamctx status
teamctx refresh
teamctx context
teamctx why <card-id>
teamctx open-source <source-or-card-id>
```

Tasks:

- Keep fixture mode working.
- Add a local project config file for opted-in source settings.
- Render context for the current repo/task scope.
- Show source-openability in terminal output without exposing source body text
  by default.
- Make `why` explain provenance and policy denial plainly.
- Keep `open-source` read-only and policy-gated.

Acceptance criteria:

- CPO can run one scripted demo from a local repo.
- The default output is compact enough to read at terminal start.
- The output does not require TeamCtx vocabulary to understand.
- `open-source` never prints blocked or unavailable body text.

## Workstream 5: Product Language And Docs

Owner: CPO with CTO support

Goal: make the product understandable without training the user on internal
terms.

CPO decisions needed:

- Keep or replace `Working context`.
- Keep or replace `Source opening`.
- Decide whether `body available` is too implementation-shaped.
- Decide whether `Open source` should become concrete per source family:
  `Open PR`, `Open issue`, `Open doc`.
- Decide whether `Use in this session` remains the temporary context action.

Deliverables:

- One product language memo.
- Updated README/product docs for the vertical slice.
- One example terminal transcript using only user-facing language.

Acceptance criteria:

- A user can understand the context packet without knowing benchmark terms,
  promotion, memory, registry, or source routing.
- The docs describe what TeamCtx does and does not read.
- The docs preserve the token/time savings promise without overstating it.

## Definition Of Done

- Full test suite passes.
- Ruff and mypy pass.
- `git diff --check` passes.
- Secret scan passes on committed artifacts.
- New public/product claims have tests or benchmark evidence.
- Docs are updated with honest limitations.
- Work is committed and pushed at least daily.

## Sprint Risks

- GitHub auth and local environment friction could eat time.
- Source-openability language may help one model and not another.
- The collision benchmark may require stricter task wording, not just scoring.
- Core contracts may tempt over-abstraction.
- A live connector can accidentally pull too much data if the allowlist is not
  enforced first.

## Explicit Tradeoff

This sprint optimizes for product truth over feature breadth.

If the sprint succeeds, we will have a small but real product spine: deterministic
context from one real source family, compact terminal output, explicit source
health, and a safe open-on-demand path. That is better than a larger demo that
quietly violates the product promise.
