**REFEREE REPORT**

**Paper:** “Certified Context for Autonomous Coding Agents: A Deterministic Mediation Protocol with Coverage Guarantees”

---

### 1. Summary of Claims

The paper proposes `teamctx`, a deterministic broker that replaces best-effort retrieval for agent context with a *certified mediation* protocol. It claims to deliver four structural properties—determinism, permission noninterference, evidence/instruction separation, and no-silent-omission—via a pure card generator over a permission-filtered snapshot, and asserts that the resulting *coverage certificate* `κ` dissolves the “absence-as-clearance” fallacy.

### 2. Soundness of Theorems T1–T5

**T1 (Determinism).** The proof sketch states that `g` is a composition of pure functions and that `S` and `t` are explicit parameters. This is vacuously true *if* the snapshot `S` is itself a deterministic function of the event logs. The paper hand-waves that `S` is “a deterministic fold over the logs,” but never specifies the ordering guarantees required to make that fold deterministic. In any distributed system, event arrival order is non-deterministic unless a total order is enforced (e.g., via a sequencer or consensus). The paper admits sources are semi-trusted and that `Adv₃` can delay or drop events, yet fails to state whether the broker assumes a globally consistent event log. Without that assumption, `S` is not a function of wall-clock time alone, and T1 collapses. **Missing assumption:** a total order on events per source, or a proof that the fold is commutative and idempotent (CRDT-style), which is not provided.

**T2 (Permission noninterference).** The statement “If `S|_P = S′|_P` then `g(S,q,P) = g(S′,q,P)`” is a standard noninterference property, and the sketch correctly notes that `π_P` is applied first. However, the output includes `κ`, which is defined as `{ (σ, t_obs(σ), status(σ)) : σ ∈ Req(q) }`. `Req(q)` is computed from `R_k(q)` *independently of permissions*. If a source `σ` is required but `P` has no visibility into any of its artifacts, `σ` will still appear in `κ` with a status, thereby leaking the existence of that source. The paper’s own limitation (§8) concedes that “κ must be permission-scoped,” but the theorem as stated does not enforce this. The corollary that “B's output reveals no information about artifacts P cannot see — including their existence” is **false** under the given definitions. This is not a side channel; it is a direct violation of the claimed property. The fix (filtering `κ` by `vis_P`) would then reintroduce silent omission at the permission level, contradicting T5.

**T3 (Evidence/instruction separation).** The claim that “source content cannot influence which cards are produced” rests on the assertion that `rules`/`rank` branch only on typed metadata, never on payload bytes. The paper lists card kinds such as `acceptance_criteria_changed` and `linked_issue_changed_after_branch`. Detecting a change in acceptance criteria typically requires comparing the body of an issue across versions—i.e., processing payload bytes. If the broker performs such a diff, then payload *does* influence card production, and the lemma is false. If instead the broker relies solely on source-provided metadata (e.g., a “modified” flag), then the broker’s correctness depends on the source’s honesty in providing that flag, which is an untrusted input. The paper never clarifies this design choice, leaving T3 either unsupported or reliant on a trust assumption that contradicts the threat model. The agent-cooperation caveat further guts the practical import: the broker may be injection-resistant, but the agent is not, and the paper provides no mechanism to enforce the typing on the agent.

**T4 (Soundness/no fabrication).** The theorem states that every card has a “witness artifact `a ∈ S|_P`.” But cards like `source_unavailable` are triggered by the *absence* of a reachable source, not by an artifact. The proof sketch says “rules only constructs a card when its triggering artifacts are present,” which is directly contradicted by the existence of such cards. The witness should be the observation record, not an artifact. This is a minor definitional sloppiness, but it indicates the formal model is not tight.

**T5 (No-Silent-Omission).** This is not a theorem but a design invariant: the response always includes `κ`. The paper elevates it to a “calculus” and claims it “dissolves” the absence-as-clearance fallacy. In reality, it merely relocates the burden: the agent must now interpret the absence of cards *within* the region described by `κ`. If the agent ignores `κ` or misinterprets it, the fallacy persists. The protocol does not *force* correct interpretation; it only provides information. Thus, the claimed dissolution is a property of the consumer, not the system, and is unenforceable. The “guarded claim” semantics is well-defined but trivial: it says “C is sound over region(κ); outside region(κ): unknown.” That is exactly what any system with a query log could say.

### 3. Central Contribution: Coverage Certificate and No-Silent-Omission

The coverage certificate is essentially a query manifest: a list of sources consulted and their freshness. This idea is not novel. Database literature has studied *query completeness* for decades (e.g., Motro, “Completeness information and its application to query processing,” VLDB 1989). Distributed systems routinely return metadata about which replicas were contacted (e.g., Cassandra’s `QUORUM` responses include node lists). The paper’s claim that this “dissolves” the absence-as-clearance fallacy is rhetorical overreach. The fallacy is a cognitive error; providing a certificate does not prevent the agent from committing it. At best, `teamctx` makes the bounds of ignorance explicit, which is good engineering hygiene but not a formal breakthrough. The “No-Silent-Omission” property is simply the absence of a “null” response; it does not guarantee that the broker has not omitted sources it *should* have queried but didn’t (the relevance ceiling). So the protocol still silently omits sources outside its structural reachability, contradicting the spirit of the claim.

### 4. Noninterference (T2): Real Noninterference or Access Control + Relabel?

T2 is a standard noninterference property, but it is achieved by a trivial access-control check (`π_P`) and then a pure computation. This is not a new insight; it is the definition of a reference monitor that enforces a security policy. The paper’s contribution is merely to state that the monitor is deterministic and that the output is a function of the visible subset. The real challenge in noninterference is handling *implicit flows* and side channels. The paper acknowledges side channels (§8) but dismisses them as “coarse information.” The strongest objection is the one already raised: `κ` leaks source existence unless filtered, and filtering `κ` reintroduces silent omission. This tension is unresolved. A proper noninterference result would require a proof that the entire output, including `κ`, is a function of `S|_P` alone. The paper does not provide this, and the current definition of `κ` violates it.

### 5. Separation (T3): Payload Control-Flow Irrelevance and Agent Cooperation

The lemma that “payload is control-flow-irrelevant in `B`” is the linchpin of injection resistance. As argued above, it is unsubstantiated because the paper does not specify how change-detection rules work. If they inspect payload, the lemma fails. Even if they don’t, the agent-cooperation caveat admits that the agent may still execute quoted content. The paper claims this is a feature: “it gives the agent a machine-checkable boundary it *can* enforce.” But if the agent is untrusted (Adv₄), it will not enforce it. If the agent is trusted, then why is injection resistance needed? The paper’s threat model includes a malicious source author (Adv₁) who wants to inject instructions into the agent. The broker’s typing does nothing if the agent chooses to treat `quote(·)` as executable. The paper thus solves the easy problem (protecting the broker) and leaves the hard problem (protecting the agent) to the agent developer. This is a significant limitation that undercuts the practical contribution.

### 6. Prior Art

The paper positions itself as a synthesis of reference monitors, IFC, LangSec, and bounded staleness. However, the individual pieces are well-trodden:

- **Reference monitors with audit logs:** The broker is a read-only reference monitor that produces a signed, replayable output. This is standard practice in high-assurance systems (e.g., SELinux audit logs, or more directly, the *Query Log* in database systems).
- **Provenance and completeness:** The coverage certificate is a form of *why-not* provenance combined with a freshness token. Systems like *Trio* (Widom, 2005) and *ORCHESTRA* (Ives et al., 2008) tracked data lineage and completeness. The paper does not cite any work on data provenance for AI agents (e.g., *Model Cards*, *Datasheets for Datasets*).
- **Injection resistance via typing:** The idea of separating data from instructions using a typed channel is the core of LangSec (Sassaman et al., 2011) and has been applied to LLMs in works like *Structured Access* (Gehrmann et al., 2022) and *Guardrails
